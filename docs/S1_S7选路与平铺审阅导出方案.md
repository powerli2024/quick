# s1、s7 与 MossFormer SE 完整选路及平铺审阅导出方案

## 1. 目标与最终产物

本方案只讨论一个冻结的 s1 阶段和一个冻结的 s7 阶段如何组合，不使用跨 s1–s8 的测试集神谕。
每个 UID 同时保留：

- s1 的全部 raw 流；
- s1 每条 raw 流对应的 MossFormer2_SE_48K 视图；
- s7 冻结 arm 的全部 raw 流；
- s7 每条 raw 流对应的 MossFormer2_SE_48K 视图；
- 一个最终 winner；
- 一个逐 UID 的选路原因 JSON。

最终生成一个平铺审阅目录。按文件名升序排列后，同一个 `(split, uid)` 的所有文件自然连续成组，
最终 winner 位于该组第一条，选路原因 JSON 位于该组末尾。这个目录用于人工听审、复盘和错误分析，
不能直接冒充 extract-main 所需的 selected-only `best_sep` 目录。

完整工作流与指标定义以 [`KWS完整工作流.md`](KWS完整工作流.md) 为上位约束；本文进一步冻结 s1+s7
的决策顺序、文件命名和 JSON 契约。

## 2. 必须先冻结的输入

### 2.1 阶段 arm

正式复验必须显式给出：

```text
s1_arm = s1_onnx_full
s7_arm = 一个在开发集锁定、且 pos/neg 标签完全一致的 s7 arm
```

例如 `s7_cv_then_onnx_gate/thr_a` 只能在开发实验确认后写入配置。`S7_ARM=auto` 只能用于摸底，不能在
最终测试集重新选择 arm。s7 某 UID 不存在时记录 `s7_available=false`，不能从其他 s7 阈值臂临时补齐。

### 2.2 候选身份

一个候选引用由下式唯一表示：

```text
(split, uid, role, arm, stream, view)

role   = s1 | s7
view   = raw | moss48k
stream = original | spk1 | spk2 | ...
```

`original` 在 extract-sep 的 WAV 文件名中可能对应 `peak`，导出和 JSON 中统一写语义名 `original`，同时
保留 `source_wav`，不能因源文件标签不同创建两份候选。

### 2.3 模型和阈值签名

一次正式运行至少冻结：

```text
extract_sep_run_id
s1_arm / s7_arm
asr_model_hash / asr_context_mode
english_alias_table_hash
qkw_calibrator_hash（没有则明确为 null）
mossformer_model_hash / inference_signature
speaker_encoder_hash
noise_model_hashes
route_policy_hash
```

任一签名变化必须使用新的工作目录，不得把旧 ASR、SE、embedding 或噪声结果混入本轮。

## 3. 音频去重与一次计算

### 3.1 两种哈希

同时保存：

```text
file_sha256 = 原始文件字节哈希
pcm_sha256  = 统一解码为 mono PCM 后的波形哈希
```

`pcm_sha256` 是 canonical audio id。相同波形即使路径、WAV 头或阶段 alias 不同，ASR、NLL/q_kw、
embedding、VAD、噪声、音乐和感知质量都只计算一次。阶段候选只引用该 canonical feature record。

MossFormer 缓存键为：

```text
(raw_pcm_sha256, mossformer_model_hash, inference_signature)
```

相同 raw 波形只执行一次 SE；输出再按 `se_pcm_sha256` 去重，后续特征同样只计算一次。去重只减少推理，
不会删除阶段/stream 的语义候选。平铺审阅目录为了让每个流都可见，可为相同 PCM 创建多个硬链接；
硬链接失败时才复制，并在 JSON 记录 `materialize_mode=copy`。

### 3.2 一次计算不等于少报阶段

如果同一 PCM 同时出现在 s1/spk1 与 s7/spk1，它在 feature registry 中只有一条记录，但两个候选引用
都必须出现在逐 UID JSON 和平铺目录中。报告同时给出：

```text
n_candidate_refs
n_unique_raw_pcm
n_unique_se_pcm
feature_cache_hit
feature_cache_miss
```

不得为了得到“更好的一次 ASR”重复推理同一音频；同一音频、文本、语言和模型签名只能有一个 ASR 结果。

## 4. 每个候选必须具备的评价字段

### 4.1 文本硬指标

定义统一选路 CER：

```text
CER_route = CER_pinyin_toneless               # 中文
CER_route = CER_alias                         # 英文，别名表预先冻结
```

英文还必须保留严格 `CER_char`、`wake_coverage`、`extra_ratio`、命中的 alias 和 `core_hit`。例如：

```text
A("hicolmo") = {"hicolmo", "heycolmo", "hi colmo", "hey colmo"}
CER_alias(r,h) = min[a in A(r)] CER_char(a,h)
```

`colmo` 等核心品牌词缺失时 `core_hit=0`，即使宽松文本距离较低也不能作为正常英文注册候选。别名禁止
在看过最终测试 ASR 后追加。

这里“低 CER 是硬指标”首先表示：任何 q_kw、声纹、SNR、DNSMOS 或听感都不能让更高
`CER_route` 的候选越过更低 `CER_route` 的语义有效候选。它不等于强制每个 UID 必须 CER=0；若所有
候选均非零，为保证全 UID 覆盖仍选其中最小者，并在 JSON 标记 `low_cer_status=min_nonzero`。如果产品
另有绝对拒绝阈值，应在开发集按语言和唤醒词长度冻结 `cer_accept_thr`，作为独立的注册接受门。

### 4.2 q_kw

```text
NLL = -mean_t log P(y_t | y_<t, audio)
q_kw = Calibrate_lang(-NLL)
```

只有独立校准集拟合并冻结后的 `q_kw` 才能使用绝对阈值和跨 UID 解释。没有校准器时，raw NLL 只能在
同一 UID、完全相同 `CER_route` 的候选之间破同分；JSON 必须写 `score_kind=nll`。

### 4.3 ASR 内容类别

每条 raw/SE 都保留 ASR 文本并分为：

```text
target_wake
target_plus_interference
competing_speech
noise_or_music
uncertain_or_hallucination
```

分类依据是 CER、核心词、目标覆盖、额外文本、speech ratio、音乐概率、重叠语音及 ASR 置信证据。
SE 后 CER 上升只记录 `delta_CER`，不能单独硬拒绝：竞争人声或噪声流被 SE 抑制后，ASR 文本变化并不
等价于目标说话人受损。最终 winner 仍必须从语义有效候选中按最低 CER 选择。

### 4.4 噪声、音乐与物理质量

每个 canonical raw 和 SE 音频都计算相同冻结指标：

- duration、RMS、peak、clip rate、DC offset、zero/silence ratio；
- VAD speech ratio、最长连续语音段；
- 仅在适用时计算的 VAD-SNR proxy；
- spectral flatness、spectral flux、低/中/高频带能量比例；
- `p_music` 及 top-k 音乐、乐器、歌声类别；
- `p_overlap`、估计说话人数及竞争人声时长；
- DNSMOS SIG/BAK/OVRL，可选 SRMR、DRR/T60 proxy。

这些指标用于解释候选和同 CER 的末级破同分，不能作为一个任意加权的“纯净度总分”。明显损坏文件，
如无法解码、空音频、非有限采样值或严重长度不匹配，属于 `fatal_invalid`；音乐概率高、SNR 低或
DNSMOS 低本身只标记风险，不能在未经校准时直接否决。

### 4.5 声纹证据

```text
c_change = cos(embed(SE), embed(raw))
```

`c_change` 可以计算并报告分位数，但默认不使用 `0.90/0.92` 硬门，也不用于给候选排序。raw 本身可能
被噪声或第二说话人污染，SE 真正改善时 cosine 也可能下降。

如果有独立的同说话人参考 `ref`，使用：

```text
gain_ref = cos(embed(candidate), embed(ref))
           - cos(embed(raw_parent), embed(ref))
```

没有独立 reference 时不伪造单条声纹增益，最终由冻结 CMD/Presence 的 FRR/FAR 验证。

## 5. 完整逐 UID 选路机制

### 5.1 第一步：建立全部候选，不提前删 SE

对每个 UID 生成候选全集：

```text
C(uid) = s1_raw_all_streams
       ∪ s1_moss48k_all_streams
       ∪ s7_raw_all_streams
       ∪ s7_moss48k_all_streams
```

raw 永久保留。MossFormer 输出缺失、长度异常或推理失败必须写入失败候选和审计统计，不能静默少一条。
`delta_CER>0` 或 `c_change<0.9` 不删除记录。

### 5.2 第二步：候选有效性分层

每条候选分成三层：

1. `fatal_invalid`：文件不存在、无法解码、空波形、采样非有限、SE 长度契约失败或核心评分缺失。
2. `semantic_ineligible`：英文 `core_hit=0`，或多项冻结证据共同确认其为非目标/ASR 幻觉。
3. `rankable`：可以参加阶段内排名。

噪声大、音乐概率高、SE 后 CER 上升、`cos(SE,raw)` 下降都不能单独把候选放入前两层。所有三层候选
都保留在 JSON 和审阅目录中，只有 `rankable` 参加正常选路。

### 5.3 第三步：分别选出 s1 和 s7 的阶段 winner

在同一 role 的 raw 和 MossFormer 视图中按字典序选择：

```text
L1  最小 CER_route
L2  最大 calibrated q_kw；无校准器时为最小 target NLL
L3  最大独立同说话人参考分数（仅在确有独立 ref 时）
L4  更低 extra_ratio、更低竞争/重叠人声风险、无物理损坏
L5  raw 优先
L6  original 优先
L7  固定 stream 顺序：original, spk1, spk2, ...，未知名称按字典序
```

L2–L4 只能在 L1 完全相同的集合中使用。使用 calibrated q_kw、独立声纹和质量指标切换时，还必须达到
预先冻结的最小增益 margin；低于 margin 视为同分，继续执行保守回退。由此得到：

```text
w1 = stage_winner(s1 raw + s1 moss48k)
w7 = stage_winner(s7 raw + s7 moss48k)
```

如果某阶段没有 rankable 候选，记录 `stage_status=no_rankable_candidate`，不能偷偷从另一个 arm 取音频。

### 5.4 第四步：决定是否打开 s7

离线实验会评分所有 s7 音频；这里的“打开”只表示部署决策是否允许 s7 替换 s1，不表示此时才计算 s7。
s7 trigger 为以下任一项：

- s1 没有 rankable 候选；
- `CER_route(w1) > 0`；
- calibrated `q_kw(w1) < qkw_low_thr`，且阈值已在独立开发集冻结；
- w1 被多项证据标为 `semantic_suspect`；
- w1 出现冻结的物理灾难条件，如严重削波或有效语音几乎为空。

没有 q_kw 校准器时，不允许用 raw NLL 的跨 UID 绝对阈值触发 s7。若 w1 为 CER0、语义可信且无灾难
问题，默认保持 s1，不因为 s7 的听感、SNR 或 DNSMOS 更好而打开切换。

### 5.5 第五步：s7 只能按严格证据切换

若没有触发 s7、s7 不可用或 s7 无 rankable 候选，保持 w1。其余情况按顺序判断：

1. `CER_route(w7) < CER_route(w1)`：切换到 w7。
2. `CER_route(w7) > CER_route(w1)`：保持 w1，任何其他指标不得覆盖低 CER。
3. CER 完全相同且 calibrated `q_kw(w7)-q_kw(w1) >= qkw_switch_margin`：切换到 w7。
4. 没有校准 q_kw 时，仅允许在同 UID 同 CER 下比较 NLL；达到冻结的 NLL margin 才切换。
5. 文本证据仍同分时，只有独立同说话人参考显著改善、且物理/语义质量不退化，才允许切换。
6. 仍同分或证据冲突：保持 s1。

若 `pcm_sha256(w7) == pcm_sha256(w1)`，两者是同一音频，直接保持 s1 alias，原因写
`SAME_AUDIO_KEEP_S1`，不能把 alias 变化统计为 s7 提升。

### 5.6 第六步：无正常 winner 的处理

为保证审阅包 100% UID 覆盖，每组必须有一个 `0000__SELECTED` 文件：

- s1 无有效候选但 s7 有：选择 w7，标记 `SWITCH_S7_S1_UNAVAILABLE`；
- s1/s7 都无 rankable 候选：从可解码的 s1 raw 中按最低 CER 确定审阅 fallback；
- 连 s1 raw 都不可解码：本组导出失败，整次正式导出 `NO_GO`，不得生成空 WAV 冒充 winner。

第二种情况必须写 `selection_mode=audit_fallback`、`production_eligible=false` 和
`requires_manual_review=true`。它只是保证审阅有明确首项，不等于获准进入生产注册集。

### 5.7 选路伪代码

```text
for each (split, uid):
    C = collect_all_s1_s7_raw_and_moss_views(uid)
    score_each_canonical_audio_once(C)
    annotate_validity_and_content_class(C)

    w1 = stage_winner(rankable(C, role="s1"))
    w7 = stage_winner(rankable(C, role="s7"))

    if w1 is None:
        selected = w7 or audit_fallback_s1_raw(C)
    elif not trigger_s7(w1):
        selected = w1
    elif w7 is None:
        selected = w1
    elif pcm_sha256(w7) == pcm_sha256(w1):
        selected = w1
    elif CER_route(w7) < CER_route(w1):
        selected = w7
    elif CER_route(w7) > CER_route(w1):
        selected = w1
    elif calibrated_qkw_gain(w7, w1) >= frozen_margin:
        selected = w7
    elif independent_speaker_gain(w7, w1) >= frozen_margin
         and quality_not_worse(w7, w1):
        selected = w7
    else:
        selected = w1

    export_all_candidates_once_as_aliases(C, selected_first=True)
    write_route_reason_json(C, selected, complete_decision_trace=True)
```

## 6. 冻结原因码

原因码必须机器可统计，详细中文说明另放 `reason_text`。至少支持：

| reason_code | 含义 |
|---|---|
| `KEEP_S1_CER0_TRUSTED` | s1 为 CER0、语义可信，未触发 s7 |
| `KEEP_S1_S7_UNAVAILABLE` | 已触发，但冻结 s7 arm 无该 UID |
| `KEEP_S1_S7_NO_RANKABLE` | s7 没有可排名候选 |
| `KEEP_S1_LOWER_CER` | s7 CER 更高，硬性保持 s1 |
| `KEEP_S1_TIE_NO_GAIN` | CER 相同但 q_kw/NLL/独立声纹增益不足 |
| `SAME_AUDIO_KEEP_S1` | s1、s7 winner 为同一 PCM，只保留 s1 决策身份 |
| `SWITCH_S7_LOWER_CER` | s7 严格降低 CER |
| `SWITCH_S7_EQUAL_CER_QKW_GAIN` | 同 CER 下冻结 q_kw 显著改善 |
| `SWITCH_S7_EQUAL_CER_NLL_GAIN` | 未校准模式下，同 UID 同 CER 的 NLL 显著改善 |
| `SWITCH_S7_EQUAL_CER_SPK_GAIN` | 同 CER/文本证据下，独立声纹证据显著改善 |
| `SWITCH_S7_S1_UNAVAILABLE` | s1 无 rankable 候选，使用 s7 |
| `AUDIT_FALLBACK_S1_RAW` | 无正常 winner，为审阅完整性回退到可解码 s1 raw |
| `FAIL_NO_DECODABLE_S1` | 无法形成审阅 winner，整次导出失败 |

阶段内还应单独记录 `view_reason_code`，例如 `MOSS_LOWER_CER`、`MOSS_EQUAL_CER_QKW_GAIN`、
`RAW_LOWER_CER`、`RAW_CONSERVATIVE_TIE`，避免最终原因只说明 s1/s7，却无法解释为何选择 raw 或 SE。

## 7. 平铺目录与文件名设计

### 7.1 单目录结构

```text
WORK_DIR/review_flat/
├── G000001__pos__U-pos_0001-a1b2c3d4__0000__SELECTED__s1__raw__spk1__P-11aa22bb.wav
├── G000001__pos__U-pos_0001-a1b2c3d4__1000__CAND__s1__raw__original__P-33cc44dd.wav
├── G000001__pos__U-pos_0001-a1b2c3d4__1001__CAND__s1__raw__spk2__P-55ee66ff.wav
├── G000001__pos__U-pos_0001-a1b2c3d4__2000__CAND__s1__moss48k__original__P-77aa88bb.wav
├── G000001__pos__U-pos_0001-a1b2c3d4__3000__CAND__s7__raw__original__P-99cc00dd.wav
├── G000001__pos__U-pos_0001-a1b2c3d4__4000__CAND__s7__moss48k__original__P-aabbccdd.wav
├── G000001__pos__U-pos_0001-a1b2c3d4__9000__ROUTE_REASON.json
├── G000002__pos__U-pos_0002-e5f6a7b8__0000__SELECTED__s7__moss48k__spk1__P-eeff0011.wav
├── ...
├── ZZZZZZ__EXPORT_INDEX.jsonl
└── ZZZZZZ__EXPORT_SUMMARY.json
```

所有候选音频和逐 UID 原因 JSON 都直接位于 `review_flat`，不创建 UID 子目录。文件名只使用 ASCII、
数字、`-` 和下划线，唤醒文本不进入文件名，避免中文路径、空格和 shell 转义问题。

### 7.2 文件名前缀

```text
G{group_order:06d}__{split}__U-{uid_slug}-{uid_hash8}
```

- `group_order`：对 `(split_order, natural_uid_key, exact_uid)` 稳定排序后从 1 编号；固定六位保证普通
  字典序、Windows 资源管理器和 Linux `sort` 一致。
- `split_order`：固定 `pos=0, neg=1`，或在配置中冻结；禁止依赖目录遍历顺序。
- `uid_slug`：原 UID 的安全 ASCII 形式，最长 48 字符。
- `uid_hash8`：`sha256(split + "\0" + exact_uid)[:8]`，防止 `neg_1005cer` 等清洗后 UID 冲突。
- JSON 中始终保留未经修改的 `uid`，不能从 slug 反推真实 UID。

同一个 `(split, uid)` 的所有文件拥有完全相同的组前缀，因此按文件名排序后必然连续。

### 7.3 组内顺序

固定四位槽号：

| 槽号 | 内容 |
|---:|---|
| `0000` | 唯一最终 winner，状态写 `SELECTED` |
| `1000–1999` | 其余 s1 raw，按固定 stream 顺序 |
| `2000–2999` | 其余 s1 MossFormer SE，按固定 stream 顺序 |
| `3000–3999` | 其余 s7 raw，按固定 stream 顺序 |
| `4000–4999` | 其余 s7 MossFormer SE，按固定 stream 顺序 |
| `8000–8999` | 可选失败占位 JSON；不能创建伪 WAV |
| `9000` | `ROUTE_REASON.json` |

最终 winner 从原所属区间移动到 `0000`，不在原槽位再复制一次；其他每个候选引用恰好导出一次。如果
多个语义候选共享同一 PCM，各 alias 可以是指向同一 inode 的硬链接，但仍各有独立文件名和 JSON 记录。

完整音频名为：

```text
{group_prefix}__{slot4}__{SELECTED|CAND}__{s1|s7}__{raw|moss48k}__{stream_slug}__P-{pcm_hash8}.wav
```

精确 arm 不塞入文件名，写入每组 JSON 和全局 summary，避免 s7 长标签导致路径过长。文件名中的
`pcm_hash8` 仅用于人工识别；完整哈希必须在 JSON 中保存并用于校验。

## 8. 每组 `ROUTE_REASON.json` 契约

下面是字段结构示例，不代表具体分数：

```json
{
  "schema": "kws_s1_s7_moss_route_reason/v1",
  "group_order": 1,
  "group_key": "pos\u0000pos_0001",
  "group_prefix": "G000001__pos__U-pos_0001-a1b2c3d4",
  "uid": "pos_0001",
  "split": "pos",
  "wake_text": "hicolmo",
  "lang": "en",
  "policy": {
    "s1_arm": "s1_onnx_full",
    "s7_arm": "s7_cv_then_onnx_gate/thr_a",
```

## 9. 全局 index 和 summary

`ZZZZZZ__EXPORT_INDEX.jsonl` 每行对应一个候选引用，字段是逐 UID JSON 候选字段的扁平索引，至少包括：

```text
group_order, uid, split, candidate_id, export_name, slot,
is_selected, role, arm, stream, view, pcm_sha256,
cer_route, q_kw_or_nll, content_class, validity, loss_reason
```

`ZZZZZZ__EXPORT_SUMMARY.json` 至少报告：

- UID 总数、pos/neg 数、缺失/失败数；
- s1/s7 raw 与 MossFormer 候选引用数、unique PCM 数、缓存命中数；
- winner 的 role/view/stream 计数；
- 所有 `reason_code` 计数；
- mean CER、CER0、英文严格/别名 CER 切片；
- s7 trigger/switch 数，严格 CER 改善和同 CER q_kw/NLL 切换数；
- SE 前后 CER improved/worsened/same，按内容类别拆分；
- 噪声、音乐、竞争人声和声纹诊断的 raw/SE 分布；
- 当前模型、数据、策略和别名表完整签名；
- `production_approved=false`，直到冻结 CMD/Presence/contest 验收完成。

## 10. 导出前后的强制校验

### 10.1 导出前

- s1 必须覆盖全部预期 UID；s7 arm 标签在 pos/neg 一致。
- 每个 index UID 在 split 内唯一；内部主键使用 `(split, uid)`，不能只使用可能冲突的裸 `uid`。
- 每个 index 声明的 stream WAV 都存在且能完整解码。
- 每条 raw 都有对应 MossFormer 输出或显式失败记录。
- ASR、SE、q_kw、embedding、噪声特征签名一致。
- 同一 score key 只能有一条确定性结果。

### 10.2 导出后

对按文件名排序后的完整目录执行断言：

```text
每个 group_prefix 只出现一个连续区间
每组恰好一个 0000__SELECTED WAV
0000__SELECTED 是该组第一条音频
每组恰好一个 9000__ROUTE_REASON.json
JSON 的 selected_export_name 与实际 0000 文件一致
JSON candidates 数量等于该组候选 WAV 数量
所有导出 WAV 的完整 PCM hash 与 JSON 一致
所有候选引用恰好导出一次，无 basename 冲突
所有失败均有记录，不能静默缺文件
全部预期 UID 均有组；否则整次正式导出 NO_GO
```

还要随机抽取并人工听审：s1 raw/SE、s7 raw/SE、低 cosine 但被选、CER 退化的干扰流、音乐高概率流、
英文 alias 命中流及所有 `audit_fallback`。人工听感只用于发现系统性错误，不反向修改最终测试阈值。

## 11. 与生产 selected-only 目录的关系

平铺目录用于审阅，不符合 extract-main 常用的：

```text
best_sep_selected/
├── pos/{uid}.wav
├── neg/{uid}.wav
└── index.jsonl
```

只有平铺目录校验通过后，才从每组 `0000__SELECTED` 物化 selected-only 目录。selected-only 的
`index.jsonl` 必须保留 `review_group_prefix`、`route_reason_json`、完整源路径和哈希，使任一生产 WAV 都能
回溯到全部候选及决策过程。不能从目录中再次按听感选文件，也不能重新运行 selector 得出不同 winner。

selected-only 仍需做冻结 CMD FRR/FAR 和 extract-main Presence、真实 ASR、contest 验收；平铺包生成成功
只证明选路和证据可审计，不代表生产批准。

## 12. 当前实现与目标方案的差距

当前 `scripts/run_se_route_eval.py` 已具备 s1/s7 inventory、raw/SE 评分、哈希复用和 selected-only 导出
基础，但还不满足本文目标：

- 当前 SE 使用 `CER_se<=CER_raw+slack` 与 `cos(SE,raw)>=threshold` 作为资格门；目标方案要求完整保留
  并评分所有 SE，把配对 CER/cosine 改为诊断和原因字段，最终仍按低 CER 选路。
- 当前英文主指标是规范化字符 CER；还需加入冻结 alias CER、核心词和额外文本字段。
- 当前只输出 selected-only 路由；还需新增单目录全候选平铺导出和逐 UID reason JSON。
- 当前主要使用文件 SHA；还需明确 file/PCM 双哈希和 canonical feature registry。
- 当前没有完整的噪声、音乐、重叠人声特征表；需要对每个 unique raw/SE 一次计算、各阶段复用。
- 当前原因粒度主要是 `keep_s1/s7_no_improvement/s7_strict_improvement`；需要升级为本文冻结原因码和完整
  `decision_trace`。

## 13. 建议实现顺序

```text
I0  冻结 s1/s7 arm、模型签名、英文 alias 表和 route policy
I1  建立 file_sha256 + pcm_sha256 canonical registry
I2  对 s1/s7 全 raw 一次生成 MossFormer SE，并验证完整长度
I3  对全部 unique raw/SE 一次计算 ASR/CER/NLL/q_kw、噪声、音乐和 embedding
I4  生成候选有效性、内容类别、阶段 winner 与逐 UID decision trace
I5  运行 s1→s7 严格切换规则并生成 route reason JSON
I6  按固定 group/slot 文件名物化 review_flat，全量执行排序和哈希断言
I7  从 0000 winner 物化 selected-only best_sep，不重复选路
I8  运行冻结 CMD FRR/FAR、Presence、真实 ASR 和 contest 验收
```

这个机制保证：低 CER 始终是不可被其他分数越级覆盖的第一层证据；SE 的复杂变化被完整保留而不是
粗暴删除；s7 只在严格证据下替换 s1；同 UID 的所有 s1/s7 raw/SE 音频与选路理由能在一个目录中按
文件名自然成组，并且最终选择始终位于组内第一条。
