# quick 当前选路逻辑与合理性审查

## 1. 文档定位

本文说明 `quick` 当前代码实际执行的 s1、s7、raw、MossFormer SE 选路逻辑，并评估其合理性。事实来源是：

- `src/quick/scoring.py`：ASR/CER、q_kw、CTC、NLL、声纹、噪声与候选有效性；
- `src/quick/route.py`：同一 role 内选流、s7 触发和 s1→s7 切换；
- `src/quick/accept.py`：本地验收和 I8 生产验收；
- `configs/route_policy.json`：当前冻结参数；
- `scripts/score_wenet_ctc_manifest.py`：当前 WeNet CTC 分数定义。

本文区分“已经实现的规则”“规则是否合理”和“生产批准仍缺少的证据”。代码能输出 selected 音频，不等于该音频已经通过生产验收。

审查快照：2026-08-29，基于工作树 `HEAD=8165e7e` 及当时尚未提交的 A3/WeNet 可用性修正。后续若修改 `route.py`、`scoring.py`、`accept.py` 或 policy JSON，应同步更新本文。

## 2. 结论摘要

当前主体结构合理：

1. 每个 UID 同时保留 s1、s7 的所有流及其 MossFormer SE 视图；
2. 中文使用无声调拼音 CER，英文使用冻结 alias CER；
3. CER 是第一硬指标，较高 CER 不能被声纹、噪声、SE cosine 或听感指标直接反超；
4. s1 是默认路径，只有被触发后才比较 s7；
5. SE 不被强制接受或拒绝，而是与 raw 平等参与同 role 选流；
6. 同 CER 时才使用 q_kw、CTC、NLL、独立声纹和质量指标；
7. 全 UID 结果必须相对“最佳 s1 raw”逐条不退化，再通过 CMD、Presence 和比赛指标复验。

但当前还不是完全冻结的生产策略：

- 默认 `qkw_low_thr=null`、`QKW_CALIBRATED=0`，多数运行实际没有 calibrated q_kw；
- 当前 WeNet `ctc_align_score` 是 `1 - CTC转写CER`，不是帧级强制对齐概率；
- `0.01`、`0.10` 等 margin 还缺少独立开发集统计依据；
- 声纹 reference、噪声模型和部分质量指标可以缺失，缺失时会跳过对应层；
- 当前 I8 没有硬性要求 MossFormer 权重 hash，也允许外部结果缺少显式 `production_se=true`；
- 同一个 `quality_regression_tolerance=0.10` 被用于比例、DNSMOS 和 SNR dB，量纲不统一。

因此当前合理定位是：

> 已具备严格覆盖、CER 优先和完整审计能力的开发/复验选路器；在阈值校准、模型来源绑定和真实下游验证完成前，不是单靠本地报告即可放行的生产路由器。

## 3. 候选集合与复用

### 3.1 每个 UID 的候选

每个 `(split, uid)` 最多包含：

```text
s1 raw:       original, spk1, spk2, ...
s1 moss48k:   每条 s1 raw 对应的 MossFormer2_SE_48K 结果
s7 raw:       original, spk1, spk2, ...
s7 moss48k:   每条 s7 raw 对应的 MossFormer2_SE_48K 结果
```

- `role ∈ {s1, s7}`；
- `view ∈ {raw, moss48k}`；
- `stream` 的保守顺序为 `original, spk1, spk2, ...`；
- s7 缺少某 UID 时记录 `s7_available=false`；
- SE 失败保留 `fatal_invalid` 占位记录，不静默缩小候选数。

### 3.2 音频和特征去重

音频 identity：

```text
pcm_sha256 = SHA256(canonical_16k_float32_PCM)
```

同一波形即使来自不同 UID alias、arm 路径或 WAV 文件头，也只计算一次音频级特征。

ASR/文本分数 identity：

```text
score_key = SHA256([pcm_sha256, wake_text, lang])
```

同一音频可能对应不同注册文本，不能只用 PCM 复用 CER；同一 PCM、注册文本、语言则不重复识别。

### 3.3 raw 与 SE

SE 是 raw 的新候选而非覆盖文件。当前记录：

```text
delta_cer   = CER_se - CER_raw
cos_se_raw  = cosine(embed(SE), embed(raw))
gain_ref    = speaker_ref_score(SE) - speaker_ref_score(raw)
```

`delta_cer>0`、`cos_se_raw<0.9/0.92`、SNR/DNSMOS 下降或音乐概率上升，当前都不是单独硬拒绝门。SE 最终仍由完整排序决定。

这符合当前原则：raw 可能本身受干扰，SE 真正改善时 raw/SE cosine 也可能下降，不能盲目依赖固定 cosine。

## 4. 指标计算

### 4.1 CER：第一硬指标

#### 中文

```text
ref_py = toneless_pinyin(normalize(ref))
hyp_py = toneless_pinyin(normalize(hyp))
CER_zh = Levenshtein(hyp_py, ref_py) / len(ref_py)
```

归一化包括 NFKC、去空格、去标点和小写化。代码保留字符 CER，但 `cer_route` 使用无声调拼音 CER。

#### 英文

英文先使用冻结 alias，例如：

```text
hicolmo ↔ heycolmo ↔ hi colmo ↔ hey colmo
```

然后：

```text
CER_en = min_alias Levenshtein(normalize(hyp), normalize(alias)) / len(alias)
```

此外要求 `core_hit=true`。Colmo 系列把核心 token 归一为 `colmo`，所以 `heycolmo` 可以匹配 `hicolmo`；完全没有 `colmo` 核心的英文转写会成为 `semantic_ineligible`。

#### 选路含义

```text
CER_s7 < CER_s1  => 可切换 s7
CER_s7 > CER_s1  => 必须保持 s1
CER_s7 = CER_s1  => 才进入 q_kw/CTC/NLL/声纹层
```

比较容差为 `1e-12`，实质要求完全相同或严格改善。

### 4.2 calibrated q_kw

目标定义：

```text
q_kw = P(注册唤醒词确实存在 | 音频, 注册文本, 语言)
```

当前提供 Platt/logistic 校准工具，原始分数可以是 CTC 分或 `-NLL`，中文、英文分别拟合。

正式启用时要求：

1. 显式设置 `qkw_calibrated=true`；
2. 提供可复算 hash 的校准器 JSON；
3. 每个非 fatal unique `score_key` 都有 q_kw；
4. `0 <= q_kw <= 1`；
5. 每条记录为 `score_kind=calibrated_qkw`；
6. 每条记录的 `qkw_calibrator_hash` 与冻结校准器一致。

任一缺失、越界或 hash 不一致都会终止，不会静默降级。未显式启用时，即使 sidecar 自称提供 `q_kw=0.99`，该字段也被清空，不进入选路。

当前策略：

```text
qkw_low_thr = null
qkw_switch_margin = 0.01
```

所以绝对低 q_kw 触发 s7 当前关闭；同 CER 切换要求 q_kw 至少改善 `0.01`。

### 4.3 当前 WeNet CTC 分数

实际计算：

```text
ctc_hyp = WeNet自由解码文本
ctc_cer = CER(ctc_hyp, wake_text)
ctc_align_score = clip(1 - ctc_cer, 0, 1)
```

它是第二个 ASR/CTC 模型给出的文本证据，不是真正的帧级 CTC forced-alignment posterior，也不是跨 UID 概率。

当前只允许它在同一 UID、CER 完全相同、没有完整 calibrated q_kw、改善达到 `qkw_switch_margin` 时破同分。默认 WeNet checkpoint 只启用中文，英文 CTC 分可能为空。

### 4.4 NLL

```text
NLL = -mean_t log P(y_t | y_<t, audio)
```

NLL 越低越好。当前只在 CER 完全相同、没有 calibrated q_kw、候选池全部有有限 NLL、改善达到 `nll_switch_margin=0.01` 时使用。它不能作为跨 UID 绝对阈值。

### 4.5 声纹

当前用于选路的是：

```text
speaker_ref_score = cosine(embed(candidate), embed(independent_reference))
```

越高越好，margin 为 `speaker_switch_margin=0.01`。没有真正独立 reference 时该值应为空；`cos(SE,raw)` 只作诊断，不能当目标说话人纯度。

跨 s1/s7 的声纹切换还要求 `_quality_not_worse=true`。同 role 内，只有当前候选池全部有声纹分时才使用该层。

### 4.6 噪声、音乐和物理质量

每个 unique PCM 必算的轻量指标包括：

- 时长、RMS、peak、clip rate、DC offset、zero ratio；
- 基于 20 ms 帧能量的 `speech_ratio`、`silence_ratio`；
- 粗略 `snr_vad_db`；
- spectral flatness、spectral flux；
- 低/中/高频能量比例。

`speech_ratio` 是能量代理，不是冻结生产 VAD。

外部 noise sidecar 可补充 `p_music`、`p_overlap`、speaker count、DNSMOS、SRMR、DRR、T60 及音乐/乐器/歌唱类别。

当前实际进入选路的质量字段是：

- `clip_rate > 0.01`：触发 s7；
- `speech_ratio < 0.05`：触发 s7；
- 同 role 同 CER 后，偏向 `extra_ratio` 更小者；
- 同 role 同 CER 后，偏向 `p_overlap` 更小者；
- 声纹驱动的 s1→s7 切换要求 speech ratio、SNR、DNSMOS、音乐、重叠和 clipping 不明显变差。

其余指标主要用于报告和内容分类，并未形成统一硬门。

## 5. 候选有效性

| validity | 含义 | 参与排名 |
|---|---|---:|
| `rankable` | 音频、CER、语义条件满足 | 是 |
| `semantic_ineligible` | 可解码，但英文核心缺失或高度疑似幻觉 | 否 |
| `fatal_invalid` | 音频/SE/ASR/CER 无效 | 否 |

### 5.1 fatal_invalid

任一条件成立即 fatal：音频不可解码、空或非有限；SE 失败；没有 canonical PCM；`cer_route` 不是有限值。

### 5.2 semantic_ineligible

当前规则：

1. 英文候选没有 `core_hit`；
2. 内容分类为 `uncertain_or_hallucination` 且 `CER > 0.5`。

内容分类启发式：

```text
coverage >= 0.8 and core_hit and extra_ratio <= 0.35
    => target_wake / target_plus_interference
p_music >= 0.65 and speech_ratio < 0.35
    => noise_or_music
speech_ratio >= 0.35 and coverage < 0.5 and hyp非空
    => competing_speech
hyp为空 or speech_ratio < 0.2
    => noise_or_music
其他
    => uncertain_or_hallucination
```

这些阈值目前是工程启发式，不是独立标注数据校准结果。

`noise_or_music` 和 `competing_speech` 本身不会自动成为 fatal。这样设计是为了避免音乐背景或竞争人声存在时无条件丢掉仍含正确唤醒词的音频；它们主要用于触发 s7、解释和同 CER 排序。

## 6. 第一级：同一 role 内选流

系统先分别计算：

```text
w1 = stage_winner(all s1 candidates)
w7 = stage_winner(all s7 candidates)
```

即先在 s1 内决定哪条 raw/SE 流最好，再在 s7 内决定哪条 raw/SE 流最好，最后比较 w1 与 w7。

### 6.1 精确顺序

对某一 role：

1. 只保留 `rankable` 且 CER 有限的候选；
2. 只保留最小 CER 候选；
3. 若剩余候选全部有 calibrated q_kw，按最大 q_kw 和 margin 缩小候选池；
4. 否则若全部有 CTC score，按最大 CTC 和 margin 缩小候选池；
5. 否则若全部有 NLL，按最小 NLL 和 margin 缩小候选池；
6. 若当前候选全部有 `speaker_ref_score`，按最大声纹分和 margin 缩小候选池；
7. 若当前候选全部有 `extra_ratio`，偏向更小者；
8. 若当前候选全部有 `p_overlap`，偏向更小者；
9. 仍并列时按保守顺序。

保守顺序：

```text
raw 优先于 moss48k
original 优先于 spk1/spk2/...
spk1, spk2, ... 按编号
最后按 candidate_id 字典序
```

### 6.2 margin 的实际语义

以 q_kw 为例，设最好分数为 `q_best`：

```text
保留 q_best - q_candidate < qkw_switch_margin 的候选
```

然后按保守顺序选择。因此 MossFormer 只比 raw 高 `0.005`、margin 为 `0.01` 时，raw 仍胜；高 `0.01` 或更多时，raw 才被排除。

这种“margin 内保守”的设计合理，可减少微小数值抖动造成的切换。

### 6.3 缺失值行为

某层只有在当前候选池全部有该分数时才启用。例如三个同 CER 候选只有两个有声纹分时，整个候选池跳过声纹层。

这避免把“缺失”隐式解释为“劣质”，但也会降低指标利用率。

## 7. 第二级：是否触发 s7

得到 w1 后，满足任一条件即触发 s7：

```text
w1 不存在
or CER(w1) > 0
or calibrated q_kw(w1) < qkw_low_thr       # 当前默认关闭
or content_class ∈ {uncertain_or_hallucination, competing_speech}
or clip_rate > 0.01
or speech_ratio < 0.05
```

全部不满足则直接 `KEEP_S1_CER0_TRUSTED`。

因此当前倾向是：s1 已达到 CER0、语义可信、没有 clipping/空语音风险时，不因 s7 或 SE 的声纹稍高而改变路径。

这符合“优先 s1”的目标，但可能错过声纹纯度明显更高的 s7；是否接受该保守性应由 CMD/Presence FRR/FAR 决定。

## 8. 第三级：s1 与 s7 最终比较

### 8.1 特殊情况

1. w1 不存在、w7 存在：切 s7；
2. w1、w7 都不存在：尝试 audit fallback，否则整组失败；
3. s7 未触发：保持 s1；
4. s7 无该 UID：保持 s1；
5. s7 无 rankable winner：保持 s1；
6. w1、w7 的 `pcm_sha256` 相同：保持 s1 身份，避免同音频重复切路。

### 8.2 CER 不同

```text
CER(w7) < CER(w1) => SWITCH_S7_LOWER_CER
CER(w7) > CER(w1) => KEEP_S1_LOWER_CER
```

其他指标不能覆盖该决策。

### 8.3 CER 相同

依次判断：

1. 两边都有 calibrated q_kw，且 `q_kw(w7)-q_kw(w1) >= 0.01`：切 s7；
2. 没有可比较的 calibrated q_kw，且 `CTC(w7)-CTC(w1) >= 0.01`：切 s7；
3. 没有可比较的 calibrated q_kw，且 `NLL(w1)-NLL(w7) >= 0.01`：切 s7；
4. 声纹改善至少 `0.01`，同时质量不明显变差：切 s7；
5. 否则保持 s1。

有 calibrated q_kw 但改善不足时，CTC/NLL 不能再次翻盘；声纹仍可在质量安全条件下作为下一层证据。

### 8.4 audit fallback

只有正常 s1、s7 winner 都不存在时，系统才从“可解码且有有限 CER 的 s1 raw”中选择最低 CER 项用于听审。

该结果标记 `selection_mode=audit_fallback`、`production_eligible=false`，本地验收要求 fallback 数为 0，因此不会被当作正式通过。

## 9. reason_code

| reason_code | 含义 |
|---|---|
| `KEEP_S1_CER0_TRUSTED` | s1 CER0 且未触发 s7 |
| `KEEP_S1_S7_UNAVAILABLE` | 已触发，但 s7 无该 UID |
| `KEEP_S1_S7_NO_RANKABLE` | s7 没有可排名候选 |
| `KEEP_S1_LOWER_CER` | s1 CER 更低 |
| `KEEP_S1_TIE_NO_GAIN` | 同 CER，但其他证据未达到 margin |
| `SAME_AUDIO_KEEP_S1` | s1/s7 winner 是同一 PCM |
| `SWITCH_S7_LOWER_CER` | s7 严格降低 CER |
| `SWITCH_S7_EQUAL_CER_QKW_GAIN` | 同 CER，calibrated q_kw 显著改善 |
| `SWITCH_S7_EQUAL_CER_CTC_GAIN` | 同 CER，无 calibrated q_kw，CTC 显著改善 |
| `SWITCH_S7_EQUAL_CER_NLL_GAIN` | 同 CER，无 calibrated q_kw，NLL 显著改善 |
| `SWITCH_S7_EQUAL_CER_SPK_GAIN` | 同 CER，声纹改善且质量不明显退化 |
| `SWITCH_S7_S1_UNAVAILABLE` | s1 无 winner，使用 s7 |
| `AUDIT_FALLBACK_S1_RAW` | 仅为听审完整性回退 |
| `FAIL_NO_DECODABLE_S1` | 无法形成任何可审阅 winner |

每个 UID 的 `decision_trace` 包含 s1 winner、s7 winner、触发原因、比较值和最终 reason code。

## 10. 本地验收

基线不是固定 `s1 original`，而是：

```text
baseline(uid) = stage_winner(该 UID 的所有 s1 raw)
```

baseline 可为 s1 original、spk1、spk2 等，但不能使用 SE 或 s7。

本地通过必须同时满足：

| 检查 | 当前要求 |
|---|---|
| UID 覆盖 | `n_uid == expected_uid` |
| selected CER | 每个 UID 都有有限 CER |
| baseline CER | 每个 UID 都有有限 s1-raw baseline CER |
| paired 覆盖 | 每个 UID 都可 selected-baseline 配对 |
| audit fallback | 必须为 0 |
| missing ASR | 必须为 0 |
| 平均 CER | `mean_cer <= 0.03` |
| 逐 UID CER | `selected_CER <= baseline_CER`，恶化数为 0 |
| CER0 drop | 相对 baseline 不超过 2 个百分点 |

`allow_missing_asr` 只能继续生成审计结果，不能让验收通过。

这里的 `mean_cer` 是“每个 UID 的 CER 等权平均”，不是按拼音/字符总长度加权的 micro CER。对 KWS 注册词逐 UID 等权有一定合理性，但短词和长词的单个 UID 权重相同，报告中应明确称为 macro mean CER。

因为已经要求每个 UID CER 不恶化，`CER0 drop<=2pp` 在当前规则下基本是冗余保护：baseline 为 CER0 时 selected 不能变成非零。

## 11. I8 生产验收

本地通过后仍只是 `LOCAL_PASS_NEEDS_CMD_PRESENCE`。生产 `PASS` 还要求：

1. SE backend 为 `command` 或 `precomputed`；
2. CMD、Presence、contest 三份外部结果全部存在；
3. schema 为 `kws_i8_eval/v1`；
4. UID 数、UID fingerprint 与本轮相同；
5. `signature_hash`、selected index hash、s1/s7 arm、SE backend、ASR model hash、route policy hash 一致；
6. 中文、英文逐语言 FRR/FAR 都不恶化；
7. CMD、Presence 分别至少有一个 FRR/FAR 严格改善，另一个不恶化；
8. contest score 不低于 baseline；
9. 外部 audit 不得报告 fallback，且不能显式报告 `production_se=false`。

当前来源绑定有两个缺口：

- `mossformer_model_hash` 不是 I8 required binding；
- 外部 audit 缺少 `production_se` 时不会失败，只有显式为 `false` 才失败。

所以 `MOSSFORMER_MODEL_HASH` 当前是可选 provenance，不是 I8 硬门。更换 SE 模型必须主动更换 `INFERENCE_SIGNATURE` 或缓存目录；正式生产前建议收紧该契约。

## 12. 两种实际运行模式

### 12.1 默认未校准模式

当前 A3 最常见：

```text
CER
  → WeNet CTC 1-CER（候选池完整时）
  → NLL（有提供时）
  → 独立声纹（有提供时）
  → extra_ratio / p_overlap
  → raw、original 保守顺序
```

此时 q_kw 不参与、`qkw_low_thr` 不触发，CTC/NLL 只在同 UID、同 CER 下使用，不能把 CTC score 称为 q_kw 概率。

### 12.2 calibrated q_kw 模式

提供完整 q_kw sidecar 和冻结校准器后：

```text
CER
  → calibrated q_kw
  → 独立声纹
  → extra_ratio / p_overlap
  → raw、original 保守顺序
```

跨 s1/s7 时 calibrated q_kw 会阻止 CTC/NLL 二次翻盘。另行冻结非空 `qkw_low_thr` 后，低 q_kw 才能成为 s7 绝对触发条件。

## 13. 典型示例

### A. s1 raw CER0，s7 声纹更高

若 s1 是 `target_wake`、clip/speech 正常，则 s7 不触发，结果为 `KEEP_S1_CER0_TRUSTED`。

### B. s1 CER=0.20，s7 CER=0

结果为 `SWITCH_S7_LOWER_CER`。

### C. 同 CER，q_kw 改善不足

```text
q_kw(s1)=0.800
q_kw(s7)=0.805
margin=0.010
```

不能用 CTC/NLL 翻盘；通常保持 s1，除非独立声纹达到 margin 且质量安全。

### D. SE 后 CER 退化

raw CER=0、SE CER=0.2 时，同 role 内 raw 直接胜出，不需要额外 `CER_se<=CER_raw` 硬门。

### E. SE cosine 低但 CER 改善

raw CER=0.2、SE CER=0、`cos(SE,raw)=0.85` 时，SE 可以胜出。cosine 仅诊断，避免错误拒绝真正改善的 SE。

## 14. 合理性分析

### 14.1 合理且建议保留

#### CER 第一硬指标

注册文本已知，文本匹配可判断候选是否包含唤醒词。中文拼音 CER、英文冻结 alias 符合当前业务目标。

#### s1 优先、s7 条件触发

s1 是稳定基线，s7 是补救路径。只在 s1 文本、语义或物理质量有风险时进入 s7，可控制分布漂移。

#### raw 与 SE 并存

不要求全部采用 SE，也不使用固定 `cos(SE,raw)` 硬拒绝。让 SE 用 CER、q_kw 和下游验证证明价值更合理。

#### margin 内保守

q_kw/NLL/声纹只有微小改善时优先 raw、original，可避免模型数值噪声造成不稳定切换。

#### 逐 UID 不退化

不仅看均值，还要求每个 UID 相对最佳 s1 raw 不恶化，适合注册音频安全选路。

#### 下游 I8

CER 只能证明文本可识别，不能证明最终 KWS、Presence 或声纹验证改善；继续要求 CMD、Presence、contest 是必要的。

### 14.2 有条件合理，但必须校准

#### q_kw margin=0.01

对校准概率有一定解释性，但需要 ECE、Brier、可靠性曲线和 bootstrap 置信区间支持。目前更像工程初值。

#### NLL margin=0.01

NLL 受 tokenizer、语言、文本长度和模型版本影响。限制在同 UID、同 CER 内是对的，但 margin 仍需按模型和语言冻结。

#### CTC 破同分

独立 WeNet 比同一 ASR 的派生分更可靠，但当前 `1-CTC CER` 与第一层 CER 高度相关，不是 forced-alignment confidence。可作弱 tie-breaker，不应冒充 q_kw。

#### 内容分类

音乐、竞争人声和幻觉分类有解释价值，但 `0.8/0.35/0.65` 等阈值未基于人工标注数据校准，适合诊断和触发，不适合生产硬拒绝。

### 14.3 主要风险与建议

#### P0：SE 来源未被 I8 硬绑定

固定缓存支持 MossFormer model hash，但 I8 required bindings 未要求它。建议 I8 强制要求并匹配 `mossformer_model_hash`。

#### P0：production_se 不是必填 true

当前只拒绝 `production_se=false`，字段缺失会通过该项。建议要求 `audit.production_se is true`。

#### P1：质量 tolerance 混用量纲

`quality_regression_tolerance=0.10` 同时用于 speech ratio、音乐/重叠概率、clip rate、DNSMOS 和 SNR dB，不同量纲不可共用同一风险阈值。

建议拆成 `speech_ratio_tol`、`p_music_tol`、`p_overlap_tol`、`clip_rate_tol`、`dnsmos_tol`、`snr_db_tol`。

#### P1：speech_ratio 不是生产 VAD

帧能量代理在持续音乐、持续噪声或强混响中可能误判。建议保留作审计；若长期用于触发，应换冻结 VAD/OSD 并校准。

#### P1：质量缺失不会阻断声纹切换

`_quality_not_worse` 只比较新旧两边都存在的字段，字段缺失会被跳过。因此“质量不退化”当前实际含义是“已有可比较字段未显示退化”，不是“所有质量维度都已证明安全”。正式声纹切换应定义必需字段和最小覆盖。

#### P1：声纹 reference 契约不足

reference 必须独立。若来自当前候选或同一受污染分离输出，会形成循环证据。建议 sidecar 强制记录 reference source、speaker model hash、reference PCM hash。

#### P1：q_kw 校准质量尚未成为硬门

当前验证结构、hash、范围和覆盖率，但未检查 ECE/Brier、每语言正负样本量、独立验证 AUROC/PR-AUC、margin 置信区间和数据隔离。建议写入 calibrator artifact 并设最低验收门。

#### P1：中英文语义门不完全对称

英文明确要求 `core_hit`，中文没有等价的“核心音节必须出现”硬门，而主要依靠拼音 CER 和通用 hallucination 分类。若中文短唤醒词被长文本部分覆盖，需通过标注集验证当前 coverage/extra_ratio 是否足够。

#### P2：部分报告字段命名不精确

`n_l1_tied` 实际是经过 q_kw/CTC/NLL/质量过滤后的池大小，并非原始 CER 并列数。MossFormer 因声纹或质量胜出时，`view_reason_code` 可能仅为 `MOSS_EQUAL_CER_OTHER`。

建议分别记录 `n_rankable`、`n_cer_tied`、`n_after_text_score`、`n_after_speaker`、`n_after_quality`。

## 15. 推荐冻结顺序

1. 冻结 s1/s7 arm、ASR、英文 alias 和中文拼音 CER；
2. 只按 CER 跑全量，得到 s1 raw、s1 SE、s7 raw、s7 SE 基线；
3. 在独立开发集评估 CTC/NLL 的同 CER 判别能力；
4. 构造正负标签 q_kw 校准集，按语言报告 ECE/Brier/AUROC；
5. 冻结 q_kw threshold 和 switch margin；
6. 引入合法独立 reference 的声纹分，冻结 speaker margin；
7. 分别校准 VAD、音乐、重叠、DNSMOS 等质量阈值；
8. 做消融：CER-only、CER+SE、CER+s7、CER+s7+SE，再逐项加入 q_kw/声纹/质量；
9. 冻结 policy JSON、模型签名和 selected index；
10. 执行 CMD、Presence、contest 全覆盖 I8。

## 16. 最终判断

当前流程可概括为：

```text
完整候选
→ 有效性过滤
→ role 内 CER 优先选流
→ s1 风险触发 s7
→ s1/s7 CER 硬比较
→ 同 CER 才用 q_kw/CTC/NLL/声纹
→ 全 UID 对 s1 raw 不退化
→ CMD/Presence/contest 验证
```

最值得保留的是 CER 硬优先、s1 保守基线、raw/SE 并存、逐 UID 不退化和 I8 下游验证。

最需要补齐的是 q_kw 独立质量验收、margin 的数据依据、声纹 reference 契约，以及 MossFormer/production SE 的强来源绑定。

状态应解释为：

- `NO_GO`：本地覆盖或 CER 安全性未通过；
- `LOCAL_PASS_NEEDS_CMD_PRESENCE`：本地可进入下游复验，但不能生产批准；
- `PASS`：真实生产 SE、来源绑定和冻结外部验证都满足。当前代码对 SE 来源绑定仍有缺口，即使出现结构上的 `PASS`，也应人工核对 SE provenance。

## 17. 本次修订与落实（2026-08-29）

本节覆盖前文中“raw/original 保守优先”的旧表述。旧规则仍可作为回退时的确定性排序，但不能在 CER、文本证据和音频质量比较之前直接决定 winner。

### 17.1 `best_sep_selected` 的双文件契约

每个 UID 在 `best_sep_selected/<split>/` 下仍只有一个主文件 `<uid>.wav`，这样既有 KWS/Presence/CMD 读取逻辑无需改动。当主 winner 是 raw 时，导出器额外物化同一 raw PCM 对应的 MossFormer-48k 文件 `<uid>__se.wav`；主 winner 已经是 SE 时不复制第二份字节相同文件。

`best_sep_selected/index.jsonl` 仍保持“一 UID 一行”，新增字段：

| 字段 | 含义 |
|---|---|
| `se_wav` / `se_dest_rel` | SE 伴随文件相对路径；主 winner 为 SE 时指向主文件 |
| `se_source_wav` | SE 候选的原始导出路径 |
| `se_candidate_id` | 产生该 SE 文件的候选 ID |
| `se_pcm_sha256`、`se_file_sha256` | PCM 与文件完整性哈希 |
| `se_view`、`se_materialize_mode` | 视图和 hardlink/copy/selected_main 状态 |
| `se_is_selected`、`se_companion_missing` | 是否主选及是否缺失伴随文件 |

每个 UID 同目录还生成 `<uid>__ROUTE_REASON.txt` 作为人工审阅入口。文件开头先写明 `s1/s7`、`stream=original/spk1...`、`view=raw/SE` 的选路流程和阶段 winner，再逐候选列出 CER、ASR 文本、coverage/core/extra、q_kw/NLL、音乐/重叠/clip/speech/SNR/DNSMOS、声纹及淘汰原因。机器审计用的原始 JSON 仍保留在 `review_flat`，避免为了可读性丢失证据。

同目录同时生成 `<uid>__ROUTE_REASON.txt`。该文件先用人可读文字概述 s1→s7、raw/SE 的决策流程和最终关键值，再逐候选列出 CER、ASR 文本、q_kw/NLL、噪声、SNR、DNSMOS、声纹等评价。机器审计 JSON 仍保留在 `review_flat`，`index.jsonl` 通过 `route_reason_txt` 指向格式化文本。

伴随文件缺失会记录为审计告警，不伪造音频；正式发布前应要求 `se_companion_missing=false`。

### 17.2 所有流先生成 SE，再做公平比较

对 s1/s7 的每个 raw 流都生成 MossFormer-48k 视图，比较集合固定包含 `s1.raw`、`s1.SE`、`s7.raw`、`s7.SE`（缺失或非 finite CER 的候选只能审计，不能排名）。选路顺序为：

1. 先剔除解码失败、音频无效、CER 非 finite 的候选；
2. 以中文无声调拼音 CER、英文 normalized/alias CER 为硬主指标；
3. 在 `cer_close_delta=0.02` 的有限窗口内，依次比较已校准 `q_kw`、独立 CTC/keyword score、NLL、独立声纹分；
4. 仍接近时比较音频质量：`p_music`、`p_overlap`、`clip_rate` 越低越好，`snr_vad_db`、`dnsmos_ovrl` 越高越好；
5. 只有所有证据仍相同，才使用确定性排序。此时不再把 `original` 或 raw 作为前置优势；生产配置 `prefer_se_on_close_cer=true` 时优先保留有质量证据的 SE 视图。

“信噪比小”按音频质量的通常定义解释为噪声更小，即应选择 **SNR 更高** 的候选；若业务字段实际记录的是噪声底，应改名为 `noise_db` 并选择更低值，不能把 SNR 数值方向反过来。

近似 CER 不是无条件放宽：`s7` 跨 role 仍先执行严格 CER 比较，只有 CER 差值在窗口内且至少有一个质量维度改善、同时没有可比较维度退化，才允许质量驱动切换，并记录 `SWITCH_S7_CLOSE_CER_QUALITY_GAIN`。所有切换原因写入 route reason JSON，便于逐 UID 回放。

### 17.3 双语 Paraformer 为主 ASR，WeNet CTC 收敛为可选实验

新增 `scripts/score_paraformer_manifest.py`，按 manifest 的 `lang` 分别加载 Paraformer-zh 与 Paraformer-en，推理前按 `(score_key/PCM, wake_text, lang)` 去重，关闭进度刷屏，并保留 candidate-id 别名。部署脚本新增：

```bash
scripts/download_a3_models.sh
ASR_BACKEND=paraformer \
PARAFORMER_ZH_DIR=/root/autodl-tmp/quick_models/a3/Paraformer-zh \
PARAFORMER_EN_DIR=/root/autodl-tmp/quick_models/a3/Paraformer-en \
ENABLE_CTC=0 \
bash scripts/run_a3_route.sh
```

`ASR_BACKEND=sensevoice` 仍可复用现有 SenseVoice sidecar。WeNet CTC 默认关闭（`ENABLE_CTC=0`），避免当前日志中出现的 checkpoint 与 runtime `missing tensor/unexpected tensor` 架构不匹配污染选路；只有拿到 checkpoint 原始训练配方后，才通过 `WENET_COMMIT=<匹配提交>` 固定代码并设置 `ENABLE_CTC=1`。若无法证明模型和代码库版本匹配，应裁剪 CTC 路径，仅保留 Paraformer 双语 ASR 与已验证的 NLL/质量指标。

### 17.3.1 AutoDL 部署必须固定的路径

| 变量 | 必须指向 | 作用 |
|---|---|---|
| `QUICK_DIR` | `/root/quick` | 当前项目代码根目录 |
| `POS_NEG` | `/root/autodl-tmp/kws_sep_fullaudio_v1` | extract-sep 的 s1/s7 全音频根目录，下面必须有 `pos/`、`neg/` |

| `PRECOMPUTED_SE_DIR` | `/root/autodl-tmp/kws_se_route/se_wav` | 已完成的 MossFormer-48k 音频缓存；必须与输入 PCM 可通过哈希匹配 |

推荐直接执行以下完整命令，避免使用当前目录或隐含默认值：

```bash

```

启动前必须确认两个 Paraformer 目录存在、`POS_NEG` 的正负 UID 数量正确、`PRECOMPUTED_SE_DIR` 能覆盖全部 raw PCM。若需要完全重算 SE，应改用新的 `WORK_DIR` 与 `AUDIO_CACHE_ROOT`，取消 `PRECOMPUTED_SE_DIR` 并设置 `SE_BATCH_COMMAND`，不能把旧目录混入本次签名。

```bash
PRECOMPUTED_SE_DIR=/root/autodl-tmp/quick_audio_cache_a3_v1/se48k
```

也可以指向 `/root/autodl-tmp/quick_audio_cache/se48k`。两者择一，必须以 WAV 数量、raw PCM 覆盖率和 `se_cache_binding.json`/运行签名确认是同一 MossFormer 模型与全长推理；不要把 `sep_pcm` 填入该变量。
